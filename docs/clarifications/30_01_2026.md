## A. Assistant UI & Artifact Format

1. **Canonical artifact format for MVP**

LLM output obviously works best as markdown, but if we're doing stuff like allowing for inline comments by users inside rendered out artifacts we need to either convert to a structured JSON format or maybe decide on using a rich text editor from the get go (like TipTap or Lexical -- my two recommendations if we go that route). I'm thinking for MVP, storing markdown and converting to a blocks JSON format too would likely be the best approach. This wouldn't be for chat completions, it would only be for artifacts we're rendering outside the chat ui.

* ☐ Markdown only
* ☐ Blocks JSON
* ☐ Rich text editor state (Lexical / ProseMirror)

2. **Inline comments – timing & depth**

Are we supporting this in the MVP? The artifacts/objects I am expecting to be rendered in markdown are things like: 
- Policies / format documents -- Access Control Policy, Risk Management Policy, etc
- Control descriptions, so how logging and monitoring controls work, say
- Assessment outputs, which would be 'risk areas summary', 'controls missing evidence', etc
- Action plans? As in maybe here is a compliance roadmap for a particular policy (ISO27001 for example)
- Chat Summaries that are created inside the chat UI but then promoted to artifacts (are we doing this?)
- Explanations for evidence uploads (after upload, need to explain what the evidence is for, what it is, why it's maybe not suitable, etc)

* note. Chat messages would just be markdown and handled by the chat UI (no need to convert to blocks JSON anyway)

* ☐ Not in MVP
* ☐ MVP requires section/block-level comments
* ☐ MVP requires phrase-level inline comments

3. **Backend LLM output contract (ties in with previous stuff)**

* ☐ Markdown only
* ☐ Markdown + Blocks JSON
* ☐ Structured/editor-state JSON


4. **Change management expectations**

Are we just going with 'artifacts are immutable, each change creates a new version?' I'm assuming the data contract to be something like (version: { versionNumber: number, authorId: string, timestamp: string, changeSummary?: string}). We should just be able to see the version history for MVP? No inline suggestions or accept/reject this flow?

* ☐ Version-based audit only (v1, v2, v3)
* ☐ Track changes / suggestion mode


5. **Is raw HTML allowed in LLM output?**

I'm assuming we're not allowing this in MVP

* ☐ No (markdown-only)
* ☐ Yes (define allowed tags + sanitization rules)

!important ---> **This decision gates**:

* Markdown renderer vs rich text renderer
* Data model for artifacts
* Comment anchoring strategy
* Audit/diff strategy
